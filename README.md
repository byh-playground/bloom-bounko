# BOUNKO · 바운코

블룸 세계관의 탑다운 2D 물리 액션 공 튕기기 게임입니다. 잔상을 보내 조준·충전하고, 타이밍에 맞춰 몸체를 돌진시켜 적과 충돌합니다. 전장을 탭해 구르며 피하고, 처치로 모은 성장 자원으로 기술과 기본 능력치를 강화합니다.

게임·스타일·도움말·상세 위키는 `index.html`, 소유·편성은 `pets.js`, 공통 Unit·능력은 `abilities.js`, 종·외형은 `enemies.js`, 목표·이동 의도는 `controllers.js`, 효과음 정의는 `audio.js`에 들어 있습니다. 현재 후보 **0.12.5**는 동행 크기를 65~100%로 정규화하고 등급색 실루엣 외곽선과 탭 카드 슬롯을 적용합니다. 0.12.2의 3단계 보스·맵 확장 주기와 첫 동시 적 4마리는 유지합니다. 기존 저장·성장·전투/입력 계약을 유지하는 PATCH입니다.

## 실행

저장소를 내려받아 정적 HTTP 서버로 제공합니다. Node.js가 설치된 환경에서는 다음 명령으로 실행할 수 있습니다.

```sh
git clone https://github.com/byh-playground/bloom-bounko.git
cd bloom-bounko
npx --yes http-server . -p 8000 -c-1
```

브라우저에서 `http://localhost:8000/`을 열고 **게임 시작**을 선택합니다. 외부 라이브러리의 최초 로딩에는 인터넷 연결이 필요합니다. 공개 실행: **[BOUNKO](https://byh-playground.github.io/bloom-bounko/)**.

## 플레이와 조작

| 입력 | 동작 |
| --- | --- |
| 화면 아래 공격 버튼 / Space / Enter | 준비 상태에서 자동 조준 잔상을 발사하고, 잔상이 진행 중이면 그 방향으로 돌진합니다. 잔상의 이동과 목표까지 남은 거리에 따라 차지가 진행됩니다. |
| W / A / S / D | 위 / 왼쪽 / 아래 / 오른쪽으로 회피 대시합니다. 방향을 함께 누르면 정규화된 대각선으로 대시합니다. 새로 누를 때 1회 실행하며 길게 눌러도 반복하지 않습니다. |
| 전장 클릭 / 탭 | 해당 방향으로 구르며 이동·회피합니다. 공격 중 구르기는 진행 중인 공격을 취소합니다. |
| 대기 | 판을 마치고 대기 화면으로 돌아갑니다. |
| 설정 | 물리 실험 설정을 엽니다. 플레이 중에는 시뮬레이션이 일시정지됩니다. |
| 대기 화면의 업그레이드 / 동행 / 도움말 / 상세 위키 | 성장 기술·능력치, 알·펫 편성과 합성, 빠른 조작 설명, 전체 게임 규칙을 확인합니다. |

게임 화면에서 WASD를 사용합니다. 메뉴·입력란과 Ctrl/Alt/Meta 조합에서는 게임 입력을 제출하지 않으며, 포커스 이탈이나 메뉴 진입 시 눌림과 대기 입력을 해제합니다. WASD와 화면 클릭은 동일한 회피 충전·쿨다운·공격 취소 규칙을 적용합니다.

수동 잔상 발사에는 현재 체력의 10%가 소모됩니다. 「잔상 메아리」의 명중 후 자동 재발사는 자동 연격 중에도 체력·에너지 소모 없이 무료입니다. 자동 돌진의 별도 운동 에너지 비용은 유지됩니다. 실패한 발사에는 비용이 없습니다. 공격 성공 시 체력을 회복하며, 피해는 실제 충돌 속도로 계산합니다. 자세한 타이밍·반동·회피·보스·성장 규칙은 내장 위키를 참조합니다.

누적 처치·해금 기술·능력치 강화·알과 펫 소유권은 같은 브라우저와 같은 주소의 로컬 저장소에 보관됩니다. 진행 중인 판의 위치와 체력은 저장하지 않습니다. 저장 키 `bloom-impulse-progression-v3`는 유지하고 `{kills, unlocked, statLevels, companions:{inventory,slots,nextId}}`로 확장합니다. 기존 저장의 동행 필드가 없으면 빈 목록과 기본 1칸으로 시작합니다. 0.11.0의 현재 Definition에서 제거된 기술·선행 조건을 잃은 기술, 치명확률 투자 없이 남은 치명피해 투자만 제외해 포인트를 환불합니다. 누적 처치와 유효한 나머지 기술·스탯은 보존하고, 옛 기술 ID를 새 기술로 자동 변환하지 않습니다. 재선택할 자동 연격의 비용은 2 강화입니다.

## 영구 동행

- 실제 등록·생성 경로의 11종(신규 4종, 기존 3종, 소환 2종, 보스 2종)이 대상입니다. 첫 등장 4종은 유지하고 보충 후보에 기존 3종도 포함해 알을 획득할 수 있습니다. 보스 Unit도 generic `boss`와 별도로 실제 `speciesId`를 저장합니다.
- **피해로 확정된 적 사망마다 일반·소환 5%, 실제 보스 10%를 한 번 추첨**합니다. 같은 종의 알 1개를 지급하며 이전 보스 보장 지급을 대체합니다. 자폭 완료·소환 만료·정리·동행 사망은 추첨·처치 보상이 없습니다. 피격에서 시작된 상태 피해 처치는 적중 사망으로 처리합니다.
- 기본 동행 1칸, 슬롯 강화 4회로 최대 5칸입니다. 알과 펫은 같은 칸을 사용합니다. 장착 알은 모든 적중 처치(소환 포함)에 +1, 30처치에 같은 소유 ID·종·슬롯의 Common으로 부화합니다. 예비 알은 진행하지 않습니다.
- 모든 Common은 준비 160ms → 물리 충돌 돌진 최대 520ms → 회복 350ms를 사용합니다. 피해는 공격력 × 상대 접근 속도 / 1600이며 공통 방어·반올림·남은 HP 제한을 거칩니다. Uncommon부터 원래 종 능력이 열리고 새 능력을 억지로 추가하지 않습니다.
- 동행의 HP·피해는 등급마다 ×1.8입니다. 몸체 크기는 같은 종 적의 65/72/79/86/93/100%(Common→Mythic)이며, 스킬 범위·투사체 크기의 기존 ×1.05 성장 규칙은 유지합니다. 종의 원래 몸·질량·기본 능력을 공유합니다. 플레이어 기술·스탯·에너지를 복제하지 않습니다. 피격 보호 500ms, 사망 후 복귀 **3000ms**입니다. 복귀는 새 `unitId`와 초기화된 능력을 만들며 영구 `inventoryId`는 유지합니다.

동행 표시 정책은 `petConfig.presentation` 한곳에서 실제 등급 수로 선형 정규화합니다. `companionPresentation`의 scale은 공통 `speciesConfig`에 주입되어 Matter 반지름·수직 높이와 렌더·몸 그림자·기존 선택/피격 판정에 함께 적용됩니다. 기존 등급당 ×1.05 몸체 확대는 더하지 않습니다. 종의 같은 Presentation 그림을 사용하며, 공통 `drawSpecies`가 원래 불투명 도형의 합집합 실루엣에 2.5 월드 픽셀 등급색 테두리를 입힙니다. 몸 색과 등급색의 RGB 거리가 0.16 미만이면 0.8 픽셀 중립 대비선만 안쪽에 추가합니다. 바닥 등급 원은 제거하며 아군 소환수도 소유자의 scale/outline 정책을 이어받습니다. 그림 크기에만 적용되는 별도 축소나 적/펫 역할별 그림 복제는 없습니다.

보유 카드 탭은 첫 빈칸에 장착하고 장착 슬롯 탭은 해제합니다. 빈칸이 없으면 안내만 표시하며 자동으로 교체하지 않습니다. 기본 1칸부터 최대 5칸으로 해금하고, 빈칸·잠긴 칸을 카드 슬롯으로 구별합니다. 보유 목록은 실제 소유한 펫·알만 표시하며 같은 종·종류·등급의 보유 수, 등급색, 알의 색·무늬와 30처치 부화 진척을 재사용합니다. 잠금/합성/영구 ID·저장·Roster 경로는 유지합니다.

Common은 전종 충돌 돌진이고 이후 등급은 다음 데이터를 사용합니다. 기존 단일 행동 종은 같은 능력의 수치만 성장합니다. 원래 보스에 없는 버섯 회복은 포함하지 않습니다.

같은 종·등급 **5마리** 합성, 성공률 **64/32/16/8/4%**, 성공 5마리 소비·상위 1마리 생성, 실패 1~4마리 균등 소비는 유지합니다. 알·Mythic·명시적 잠금은 재료가 아니며 장착 자체는 보호하지 않습니다. 예비 펫 우선, 선택 등급만 연속 합성합니다. 같은 저장 키의 종 ID·소유 UID·등급·잠금·슬롯·부화 진행·발견을 보존합니다.

Unit은 몸·HP·높이·공통 피해/회복·사망을 소유하고 능력 믹스인은 각각의 준비/실행/회복 상태를 소유합니다. EnemyController/PetController는 목표·이동·공격 의도만 반환합니다. 공통 전투·성체 렌더에서 적/펫 역할로 분기하지 않으며, Presentation과 사망 정책을 주입합니다. 소환도 같은 Unit을 사용합니다. 보스 탄막 대기와 소환 제한은 **sourceUnitId/소환 소유 Unit별**이며 같은 종 보스 동행 여러 개가 서로 막지 않습니다. 투사체는 sourceUnitId/faction/payload를 보관하고 충돌·광역·투사체가 공통 hostility·피해 함수를 사용합니다. 아군 오사는 없습니다. 소환 만료는 능력 갱신 전에 처리하며 스테이지 정리는 보상 없이 탄막·소환을 정리합니다.

## 발견과 효과음

미발견 알은 정체불명의 알로 표시하되 종의 성체 Presentation에서 받은 색과 무늬를 단서로 보여줍니다. 정확한 30처치 진행도와 균열·흔들림만 먼저 드러나며 첫 부화에서 짧게 모습·이름·대표 능력을 공개합니다. 발견 기록은 보유·합성 재료 소모와 독립해 저장되고, 기존 저장의 실제 보유 펫도 발견으로 인정합니다. 일반·소환 5%와 보스 10%의 적중 사망 추첨을 사용합니다. 아직 얻지 않은 종 이름·전종 개수·미발견 빈 도감 칸을 UI·위키에 노출하지 않습니다. 합성 종·등급 선택은 현재 보유한 펫만 보여 주며 부족한 재료도 3/5처럼 표시합니다. 합성 성공률과 실패 소모·장착 재료 규칙은 유지합니다.

효과음은 펫 외에도 실제 공격·방어·성장 이벤트에 연결합니다. 충돌 강도별 타격, 수동/메아리 발사·돌진·도탄·연격 시작·충전·회피, 적 공격 준비·돌진·투사체, 보스 경고·준비·부채/원형/돌진/소환, 화염·전도·포자·실제 회복, 피격·처치·사망, 레벨·기술 투자·스테이지 시작/완료, 알·첫/반복 부화·합성 결과·펫 부활과 메뉴 조작을 구분합니다. 효과음은 실제 사건에서만 요청하며 배경 입자 프레임이나 장식 렌더에는 재생을 넣지 않습니다. 소리 합성과 재생 자원은 공통 GameKit 모듈이 소유하고 BOUNKO는 소리 정의와 이벤트 연결을 소유합니다.

로비와 설정에서 전체 음량·음소거를 바꾸고 설정에서 종류별 음량도 조절합니다. 같은 종류 최소 간격과 동시 수, 전체 최대 12음 및 우선순위로 군집 충돌을 제한합니다. master 70%·headroom 24%·compressor와 종류별 음량은 초기 추천값이며 주관적 타격감의 확정 수치가 아닙니다. 실제 포인터/키 입력 뒤 context를 열고 중단 뒤 다음 입력에서 재개합니다. 잠금·음소거 때의 사건은 버리며 나중에 몰아 재생하지 않습니다. 음량·음소거는 별도 로컬 키에 저장합니다. 단독 플레이는 직접 이벤트 재생 경로를 사용하며 두 번째 rollback 기록을 만들지 않습니다.

## 이동 구르기 강화

이동 구르기는 무료이며 공격 잔상 HP·자동 돌진 에너지와 별도입니다. 신규 이동 기술 8개는 각각 **1 강화**이고 자동 연격을 선행으로 요구하지 않습니다. 모든 단계는 기본값 대비 누적 퍼센트로 계산하며 현재 값에 연속 곱하지 않습니다.

| 가지 | 해금 효과 | 선행 |
| --- | --- | --- |
| 이동 충전 I / II | 기본 충전량 +50% / 누적 +100% (2→3→4회), 증가분 즉시 지급 | 없음 / I |
| 이동 회복 I / II | 기본 충전 시간 −20% / 누적 −40% (500→400→300ms) | 없음 / I |
| 이동 거리 I / II | 기본 이동 거리 +10% / 누적 +20%, 기존 추진력·감쇠 사용, 580ms 유지 | 없음 / I; 다른 기술의 선행 아님 |

명중 보너스는 현재 1회 충전 시간을 기준으로 하므로 기본 100ms, 회복 강화 후 80ms/60ms입니다. DoT·광역 반복 피해는 중복 발동하지 않습니다. 넘친 진행도는 다음 충전에 이어지고 가득 찬 충전에는 보너스를 저장하지 않습니다. 실제 이동 거리는 관성·마찰·장애물 충돌에 영향을 받습니다. 캐릭터 아래 표시 하나를 폭 42px로 유지하며 실제 남은 충전과 다음 칸의 회복을 2~4칸으로 보여줍니다.

기존 저장 키·형식·유효 투자는 유지합니다. 새 기술의 효과는 다시 불러올 때 적용되고 재시작은 강화된 최대 충전으로 시작합니다.

## 기술과 치명타

- 「자동 연격」은 잔상 메아리 다음에 **2 강화**로 해금합니다. 운동 에너지와 같은 대상 반복 충돌이 함께 열리며, 후속 도탄·회수·저장·절약과 조합 기술은 이 패키지를 선행으로 사용합니다. 최대 에너지 100%와 수동 잔상 타이밍 50% 이상 실제 명중의 시작 조건, 자동 돌진의 에너지 비용은 유지합니다.
- 「전도 표식」은 **2,400ms** 유지되고 다음 유효 돌진 명중 피해를 **25%** 높인 뒤 한 번 소비됩니다. 같은 명중 후 새 표식을 부여할 수 있으며 중첩되지 않습니다. 「연결 방전」은 가장 가까운 다른 적 1개에 같은 표식을 전파합니다. 도탄 구매 없이도 효과를 소비하고, 도탄 우선 선택은 추가 시너지로 남습니다. 추가 피해는 공통 방어·반올림·남은 HP 제한과 한 번의 명중·회복·처치 경로를 사용합니다.
- 기본 치명피해는 **200%**, 강화는 투자당 **+6%p**이므로 1회 206%, 2회 212%입니다. 치명확률 1회 투자 뒤 치명피해 구매가 열립니다. 강화 화면과 위키는 현재 실제 최종 배율을 표시합니다.

0.11.0에서 기존 기술 29개와 반복 스탯 8종을 감사해 기술을 28개로 통합했습니다. 0.11.1 이동 가지 추가 후 현행 기술은 36개입니다. 0.12.0은 기존 반복 스탯 8종에 동행 슬롯 투자 1종을 더합니다. 동행 슬롯만 4회 상한을 두며 기존 반복 스탯의 구매 규칙·관통 통합은 변경하지 않습니다.

## 스테이지 진행

보스는 **3·6·9…단계**의 일반 처치 목표 뒤에만 나옵니다. 나머지 단계는 목표 달성으로 바로 clear합니다. 목표는 기존 `7 + 4 × (단계 - 1)`이며 clear 뒤 1,650ms 전환·최대 HP 회복과 공격/연격/에너지/구르기 초기화를 유지합니다. 남은 적·탄막은 clear 즉시 정리하고, 알 보상은 실제 보스 처치에서만 줍니다. 적 외형·능력·개별 스탯·성장 경제·펫·잔상 비용은 이번 범위에서 바꾸지 않습니다.

맵 구간은 **1~3 → 4~6 → 7~9…**입니다. `mapTier = floor((단계 - 1) / 3)`, `radius = min(1600, 550 × (1 + 0.22 × sqrt(mapTier)))`이며 첫 보스 뒤 4단계 반경은 550→671입니다. 같은 구간은 반경·테마·지형 seed를 유지합니다. 웨이브 배치는 단계별 seed를 사용합니다. 균사 동굴의 기존 4단계 첫 해금은 유지하고 4~6 테마를 보존해 **6단계 버섯왕**으로 연결합니다. 이후 신규 테마도 확장 구간 시작(1·4·7…)을 unlockStage로 등록합니다.

동시 적은 첫 맵에서 정확히 **4마리**입니다. 그 뒤 Config의 `initialPopulation=4`, `populationPerStage=1`, `maxEnemies=82`로 `round((4 + 단계 - 1) × 현재 플레이 면적 / 첫 플레이 면적)`을 계산합니다. 구간 경계의 랜덤 다각형 때문에 계산값이 줄지 않도록 이전 목표 +1을 하한으로 삼으며 최대 82를 적용합니다. 보충도 같은 동시 생존 목표를 따릅니다. 처치 목표와 동시 생존 수는 별도입니다.

매 단계 시작에 중앙 **STAGE 번호**를 1,100ms 표시하고 사라지게 합니다. 배너는 pointer-events:none이며 입력과 게임 틱을 막지 않습니다. 단계 번호·보스 예고는 하나의 배너를 사용하고 보스 예고가 우선하며, 이전 clear 중앙 문구는 제거했습니다. 기존 stageStart/stageClear 효과음을 사용합니다.

## Pages 정적 배포

[Pages workflow](.github/workflows/pages.yml)는 main 변경과 수동 실행에서 검증한 HTML을 정적 파일로 게시합니다. 한 job에서 checkout → Pages 설정 → 파일 준비 → artifact 업로드 → 배포를 수행합니다. 별도 게임 빌드나 테스트 매트릭스는 추가하지 않습니다.

배포 파일은 index.html, pets.js, audio.js, build.json, .nojekyll입니다. HTML은 저장소의 바이트를 그대로 사용하며, [build.json](https://byh-playground.github.io/bloom-bounko/build.json)에 배포 커밋·UTC 빌드 시각·게임 버전·BUILD_ID·HTML/펫/오디오 정의 모듈 SHA-256과 고정 오디오 SDK 커밋·SHA-256을 자동으로 기록합니다. HTML의 BUILD_ID는 검증한 게임 원본을, build.json의 commit은 그 파일을 게시한 커밋을 식별합니다. 배포 상태는 저장소의 Actions에서 확인합니다.

GitHub Pages의 게시 소스는 Settings → Pages → Build and deployment → GitHub Actions입니다. 정적 파일 게시가 성공한 뒤에도 실제 공개 주소의 라이브러리 로딩과 부팅을 별도로 확인합니다.

## 네 적 · 수직 부피와 능력 믹스인 (0.12.3)

첫 웨이브 4마리와 초기 난이도 완화는 유지하며 기본 역할을 네 원본 적으로 대체했습니다. 기존 보스·소환체·펫·저장·음향 규칙은 유지합니다.

| 유닛 (IS-A Unit) | 선택 능력 (CAN-BE) | 소유 상태 |
| --- | --- | --- |
| Rogue / 그림자벼룩 | Leapable | leap.config, phase, leftMs, flight, count, landings |
| Pillbug / 폭낭 콩벌레 | SelfDestructible | selfDestruct.config, phase, leftMs, exploded |
| Thornfruit / 가시열매 | SpikeCounterable | spike.config, phase, leftMs, countered, pulses, counters |
| Rocket / 다연발 봉선화 | ArcFireable | arcFire.config, phase, leftMs, nextMs, fired, volleys, aim |

[enemies.js](enemies.js)는 실제 클래스 조합과 스펙·원본 도형 렌더를 소유하고 [abilities.js](abilities.js)는 다른 유닛/펫 호스트에도 사용할 수 있는 subclass factory 능력과 공통 좌표·궤적·충돌 함수를 제공합니다. 공개 문법은 최신 개발 규칙의 `mixin(BaseClass, ...Mixins)`와 `mixin(...Mixins)` 두 가지이며 함수 identity로 중복 적용을 막습니다. 클래스 정의 때 조합하고 생성 때 상태를 만들며 프레임마다 조합 객체를 만들지 않습니다. Host가 소유한 몸체·스탯·위치 데이터(HAS-A)를 능력 내부에 복제하지 않습니다. 이 릴리스는 실제 신규 펫 행동을 추가하지 않습니다.

재사용 Host 계약은 `Unit({id,type,body,config,adapter})`이며 body는 Matter 원형 몸체와 plugin, config는 hp/radius/height 및 해당 능력 namespace, adapter는 지형 검사·이동·추적·공격/표현 연결을 제공합니다. 능력은 자신의 namespace와 행동을 직접 소유하며 update/onHit/cancel의 의도적인 override는 super로 연결합니다. `groundArc/stepArc`는 순수 x/y 지면 + z 높이 궤적 데이터로 도약과 곡사에 같이 쓰입니다. 공통 루프에는 유닛 ID별 특수 상태 분기가 없습니다.

몸체는 발밑 `feetZ → feetZ + height` 부피입니다. 플레이어 32, 벼룩 30, 콩벌레·가시열매 38, 봉선화 42이며 기존 적·펫·일반 탄은 실제 반지름의 2배, 잔상은 14입니다. `body.plugin.volume`이 단일 권위 데이터입니다. `snapshotVolumes`는 틱 시작을 저장하고 `sweepVerticalContacts`는 solver 전에 원래 적분 끝점을 보존합니다. `contactWindow`가 XY 접촉과 수직 겹침의 시간 구간을 교차하므로 각각 다른 시점의 겹침을 합쳐 유령 타격을 만들지 않습니다. Matter 0.20.0의 Detector 결과를 Pairs/solver 전에 걸러 물리와 피해가 동일한 높이 규칙을 쓰며, 하강하면 지면에 닿기 전에도 접촉하고 기존 XY 겹침에서 재진입해도 collisionStart가 발생합니다. 수직 mover의 한 틱 통과는 beforeSolve에서 보완하고 기존 돌진의 swept 피해 보완도 같은 함수를 씁니다. Matter 원 몸체의 다각형 근사와 SAT 접점을 맞추는 보정은 Config `spatial.sweep.insetPx=1`이며 유효 XY/Z 접촉 구간을 넘지 않습니다. 정적 벽·장애물은 통과할 수 없는 지면 장벽으로 취급합니다.
