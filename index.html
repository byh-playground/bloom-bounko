1. 게임 개요와 설계 목표

BOUNKO는 블룸 세계관의 탑다운 2D 물리 액션 게임이다. 공격 버튼을 두 번 눌러 적에게 돌진하고, 전장을 탭하거나 WASD를 눌러 구르며 피한다. 멀리서 빠르게 충돌할수록 공격이 강해진다. 조작감 자체의 재미를 우선하며 성장과 이펙트는 이 흐름을 돕는다.

먼저 알아야 할 체력 규칙
① 수동 잔상 발사에는 현재 체력의 10%가 든다. 잔상 메아리의 자동 재발사는 체력·에너지 소모 없이 무료다.
② 적에게 몸이 닿거나 탄환을 맞으면 피해를 입는다. 공격 돌진 중 부딪혀도 접촉 피해가 함께 발생할 수 있다.
③ 공격으로 적에게 실제로 준 피해만큼 내 체력을 회복한다(최대 체력까지만).
④ 공격 버튼은 잔상 발사 → 돌진, 전장 탭과 WASD는 회피 구르기다.
모바일 우선탑다운Matter.js 물리Bloom GameKit랜덤 다각형 스테이지보스 탄막영구 테크트리
이 위키는 현재 단일 HTML 프로토타입의 실제 기본 설정과 동작을 설명한다. 테크트리·수치 표는 HTML 안의 런타임 Definition에서 생성한다. 이는 정식 출시 계획이 아니라 현재 실행 중인 프로토타입의 구현 기준이다.

설계 불변 조건: 첫 공격은 플레이어 입력으로 시작하며, 차지율은 초기 충격량과 비행 가속만 결정한다. 기본 직접 피해는 실제 충돌 접근 속도로 결정한다. 잔상 조준, 공격용 물리 돌진, 이동용 회피 구르기는 별도 행동이다. 표현 파티클은 HP나 시뮬레이션을 수정하지 않는다.

5. 잔상·차지·골든타임

잔상은 플레이어 본체와 별개의 경량 객체이며 등속이 아니라 로켓형 가속을 사용한다. 적 자동 조준 시 잔상이 이동하는 적을 향해 방향을 갱신하며, 본체 돌진은 발동 순간 결정된 방향을 사용한다. 잔상 충돌은 해당 틱의 적 이동량까지 고려한 상대 선분 검사로 통과 누락을 줄인다.

shadow.speed += shadow.acceleration * dt
shadow.pos += normalize(target - shadow.pos) * shadow.speed * dt
remainingGap = max(0, distance(shadow, currentEnemy) - enemyRadius - 6)
charge = clamp(1 - remainingGap / initialGap, 0, 1)

잔상 접촉은 피해를 주지 않고 적에게 물리 충격을 가한다. 기본 설정에서는 개방된 공간의 표준 적이 약 100 월드 단위 밀려나는 체감을 목표로 한다. shadow.contactPushSpeed=300은 적 질량을 고려한 초기 반동 속도(px/s)이고, shadow.contactPushControlMs=500 동안 추적 AI의 이동 보정이 실제 Matter.js 반동을 지우지 않게 한다. 기존 접근 속도가 있으면 방향 성분을 보정한 충격량(enemy.mass × max(0, speed - dot(velocity, direction)))만 주며, 좌표를 순간이동시키지 않는다. 장애물·다른 유닛과의 실제 충돌, 동작 중인 공격 패턴, 공기 저항에 따라 이동 거리는 달라질 수 있다. 보스는 공격 예고·실행 타이머를 멈추지 않는다. 적과 붙어 있어도 잔상 발사 자체를 막지 않는다. 단, 돌진은 플레이어와 현재 잔상 사이 거리가 shadow.minDashDistance 이상이어야 하며 너무 가까운 조준선은 빨간색으로 나타난다. 재발사와 발사 비용은 기존 규칙을 따른다.

차지 기준은 잔상이 이동한 누적거리가 아니라 현재 목표 표면까지 남은 거리이다. 적이 움직이면 매 물리 틱 새 거리를 반영한다. 빈 공간을 수동 잔상 발사하는 과거 기능은 현재 조작에서 제거되었지만, 내부 목적지 개념은 남아 있다.

잔상 접촉 순간 GOLDEN 상태로 들어가 차지율 100%를 제공하고 50ms 히트스탑을 적용한다. 이후 150ms COYOTE 창에는 차지율이 기본 94%에서 70%로 감소한다. 접근 말기 80% 차지부터 시뮬레이션 시간 비율 0.32의 불릿타임을 사용한다. 100% 타이밍은 최대 피해 보증이 아니다. 피해는 실제 충돌 속도가 결정한다.

VFX: 정상 거리 초록 조준 레이저 / 너무 가까운 적은 빨간 조준 레이저(발사와 밀어내기는 가능), 대상 주위 4방향 수축 에임, 잔상→표면 남은 거리 연결선, GOLDEN 금색, COYOTE 푸른 잔광. 글자 안내보다 위치·거리의 변화로 타이밍을 읽게 한다.

6. Matter.js 물리와 좌표·시간

좌표는 +X 오른쪽, +Y 아래인 월드 픽셀 기준이다. 월드 크기, 질량·반발 계수·최대 속도 등은 아래 원본 Config 표를 따른다. 중력은 0. Matter.js 0.20.0의 Engine.update를 60 TPS 고정 스텝으로 실행한다.

speedOf(body) = Body.getVelocity(body) × 60       // world pixel/second
setSpeed(body, v) = Body.setVelocity(body, v / 60)
applyImpulse(body, J): velocity += J / body.mass
Body.applyForce(body, body.position, direction × body.mass × acceleration / 1e6)

잔상 무피해 밀어내기 검증: 스카우트(질량 4.6)·중장갑(질량 8.2)·보스(기본 질량 36)를 대상으로 열린 공간에서 0.5초 후 약 100 월드 단위 이동을 목표로 한다. AI 이동 보정을 500ms 동안만 중지하되 경고·패턴 타이머를 유지한다. 장애물 앞에서는 실제 충돌에 의해 이동 거리가 제한되어야 하며 잔상 자체로 HP가 감소하거나 플레이어가 순간이동하면 안 된다.

실제 구현 단위 경계: 위 변환식은 게임 내부 월드 픽셀/초 단위를 Matter의 기본 틱 속도로 변환하는 어댑터다. 일반 이동의 위치·속도, 충돌 응답, 반동은 Matter 소유. 피해·피격 무적·HP·속성 상태는 게임 소유.

고속 충돌: Matter의 이산 물리로 빠른 돌진이 적을 관통할 수 있으므로, 이전 틱 플레이어/적 위치에서 상대 궤적의 원 교차를 계산해 가장 빠른 접촉 하나를 보완한다. 장애물과 탄막은 Matter 센서·정적 물체 충돌로 처리한다.

7. 공격·방어·회복 공식

closingSpeed = max(0, dot(playerPreVelocity - enemyPreVelocity, contactNormal))
rawDamage = isAttackingDash ? attackPower * closingSpeed / referenceSpeed : 0
criticalRaw = rawDamage * (isCritical ? criticalDamage : 1)
effectiveArmor = max(0, enemyArmor * (1 - armorPenPercent) - armorPenFlat)
outgoingDamage = round(criticalRaw * 100 / (100 + effectiveArmor))
inflicted = min(enemyRemainingHP, max(0, outgoingDamage))
heal = min(inflicted, playerMaxHP - playerHP)

충전율·이동거리의 피해 배율은 없다. 차지율은 초기 Impulse와 지속 가속만 바꾸므로 장거리 정타는 비행 중 실제 충돌 속도가 상승하는 방식으로 보상받는다. 공격마다 치명타는 criticalChance 확률로 판정하고 기본 2배(200%)에 투자당 6%p가 가산된 criticalDamage를 곱한다. 관통은 퍼센트 관통 후 고정 관통 순으로 적용한다.

체력의 기본 흐름: 직접 잔상을 발사할 때 그 순간 체력의 10%를 사용한다. 「잔상 메아리」로 명중 후 자동 재발사되는 잔상은 무료이며, 자동 연격 중에도 체력·에너지를 쓰지 않는다. 두 번째 탭의 수동 돌진은 무료이고, 자동 돌진은 별도 운동 에너지를 소모한다. 적과 몸이 부딪히면 접촉 피해를 받고, 적 탄환을 맞아도 피해와 넉백을 받는다. 반대로 내 공격이 적에게 실제로 입힌 피해만큼 곧바로 회복한다. 단, 최대 체력은 넘지 않는다.

공격 중 충돌은 서로 주고받는 것이다. 예를 들어 같은 충돌에서 내가 접촉 피해 25를 받고 적에게 실제 피해 40을 입히면 회복 40을 받아, 최대 체력 제한이 없을 경우 체력 순변화는 +15다. 적 유형별 피해·접촉 쿨타임·방어력에 따라 실제 값은 달라진다. 한 충돌에서 받은 피해와 회복을 모두 반영한 다음 사망을 판정하며, 체력 재생 스탯은 초당 HP를 추가 회복시킨다.

화염 지속 피해 역시 실제 입힌 만큼 현재 구현에서 플레이어 HP를 회복한다. 감속·충돌 등 시뮬레이션 결과 없는 단순 VFX만으로는 피해·회복이 발생하지 않는다.

8. 돌진 가속·비행·회복

돌진 시작 시 차지율을 부드럽게 매핑하여 최소/최대 초기 속도 변화를 계산하고, 그 결과의 크기에 비례하는 지속 가속을 설정한다. 발동 순간 목표 방향이 고정되고 기존 횡관성만 제거된다. 같은 속도로 충돌하면 첫 차지율이 달라도 같은 피해를 입힌다.

chargeSmooth = charge² × (3 - 2 × charge)
deltaV = dash.minSpeed + (dash.maxSpeed - dash.minSpeed) × chargeSmooth
acceleration = dash.acceleration × deltaV / dash.maxSpeed
// add charge-based impulse once, then force each fixed tick
// normal collision or swept contact resolves hit; render trail does not change physics

기본 공격 피해 유효시간은 짧은 고정 대기시간(현재 400ms)으로 끊지 않는다. 원거리 돌진은 목표까지 비행·명중 또는 속도 소멸/수명 종료 판정으로 끝난다. 최대·최소 비행 시간과 목표 거리 여유시간은 Config의 dash.flight* 설정을 참조한다. 재발사 준비는 시간과 속도 조건을 함께 본다.

이동 구르기는 무료이며 공격 잔상 HP·자동 돌진 에너지와 별도다. 이동 가지의 각 노드는 1 강화이고 자동 연격을 요구하지 않는다. 충전량 I → 명중 재충전, 충전 시간 I → 탄환 회피가 열리며 거리 가지는 독립이다. 모든 수치는 기본값 대비 누적 비율로 계산한다. 충전량은 2→3→4회이며 증가분을 해금 즉시 지급하고, 충전 시간은 500→400→300ms, 투사체 회피는 100→150ms다. 거리 증가는 이동 시간을 연장하지 않고 기존 추진력·감쇠 경로에 적용하므로 실제 거리는 관성·마찰·벽 충돌에 영향을 받는다.

명중 재충전은 실제 HP 피해를 준 공격 대시당 최초 명중 1회에 다음 이동 충전 진행도 20%를 더한다. 현재 1회 충전 시간을 기준으로 하므로 기본 100ms, 충전 시간 강화 후 80ms/60ms에 해당한다. DoT·포자·폭발의 반복 피해는 이 경로를 호출하지 않는다. 충전 완료를 넘긴 진행도는 다음 칸에 이어지며, 충전이 가득 찼으면 저장해 두지 않는다.

대시가 벽을 통과하거나 장애물을 무조건 무시하도록 위치를 직접 이동시키지 않는다. 구르기 속도는 충돌·마찰로 감소할 수 있으며 정면 방향 기준보다 역방향으로 강제 당기지 않도록 추가 속도 성분만 제거한다.

10. 자동 연격·운동 에너지·도탄

「잔상 메아리」의 명중 후 자동 잔상 재발사는 체력·에너지 소모 없이 무료이며, 자동 연격 중 생성되는 잔상도 같은 규칙을 따른다. 직접 입력한 잔상 발사는 현재 체력 10%를 사용하고, 자동 돌진에는 아래의 별도 에너지 비용이 적용된다.

자동 연격은 확률 발동을 사용하지 않는다. 「자동 연격」(2 강화)을 해금한 뒤, 처음 시작할 때 현재 최대 에너지가 100%로 가득 차고 수동 잔상 타이밍 50% 이상으로 실제 명중해야 한다. 첫 명중한 물리 틱의 실제 이동거리도 충전한 뒤 100%인지 확정한다. 연격이 시작되면 에너지가 100% 미만이어도 비용을 지불할 수 있는 한 자동 돌진을 이어 가며, 끊긴 뒤 다시 시작하려면 현재 최대 용량 100%가 필요하다.

energyCapacity = 3 × (1 + 0.5 × unlockedCapacityTiers)
autoDashCost = 1 × (1 - 0.15 × hasCostEfficiency)
energyChargePerPixel = (0.10 / (2 × player.radius)) × (1 + 0.20 × unlockedChargeTiers)
distanceRate = chainActive ? (0 + 0.50 × unlockedAutoRechargeTiers) : 1.00
energy += actualPlayerBodyDisplacement × energyChargePerPixel × distanceRate
energy = min(energy, energyCapacity)
if (manualHit && shadowCharge >= 0.50 && energy == energyCapacity): chainActive = true
if (chainActive && automaticDash && energy >= autoDashCost): energy -= autoDashCost
// 연격 종료 시 chainActive=false; 다음 시작은 현재 최대 에너지 100% 필요

평상시에는 수동 돌진·구르기·반동 모두 실제 이동 거리당 100% 효율로 충전한다. 자동 연쇄가 진행되는 동안에는 기본 충전 효율 0%이며, 「연쇄 회수 I」로 50%, 「연쇄 회수 II」로 100%까지 해금된다. 잔상의 독립 비행은 충전하지 않는다. 자동 연격에는 같은 살아 있는 대상 재공격이 기본 포함되며, 도탄 연격은 반경 내 다른 적으로 대상을 변경한다. 처치 후 추적은 죽은 대상 이후 다음 적 선택을 허용한다. 대상 탐색은 실제 거리 기반, 전도 표식이 있으면 선택 점수를 낮춘다.

충돌 회수 특성은 명중마다 20%(2단계 시 35%) 확률로 기본 비용 1칸을 회복한다. 이것은 자동 연격 발동 자체의 확률이 아니다. 에너지가 자동 돌진 비용보다 부족할 때는 자동 돌진이 실행되지 않는다. 플레이어는 직접 공격을 계속할 수 있지만, 연격 종료 후 새 자동 연격은 현재 최대 에너지 100%가 필요하다.

UI: 플레이어 주변 원형 에너지 게이지가 자동 돌진 자원을 나타내며, 게이지가 100% 차면 금빛으로 변해 새 연쇄 시작 준비를 알려준다. 실제 타이밍은 적 주변 4방향 에임이 알려준다. `×1, ×2, ×3...` 콤보는 HP를 실제 감소시킨 명중만 센다.

공통 상태는 PATROL → CHASE → WINDUP → LUNGE/발사 → RECOVER. 감지 반경 안에서만 플레이어를 추적하고 예고 중에는 정지·감속한다. 물리적 질량은 모두 플레이어보다 높아 적 공격 시 플레이어가 더 크게 튕기도록 설계됐다.

12. 보스 AI·탄막·예고

첫 보스는 고속 전투형이다. 보스전 진입 시 일반 적과 이전 탄막을 제거해 플레이어와 보스로 시작한다. 이후 공통 소환 패턴이 시작되면 제한된 수의 일시 소환수가 등장한다. 보스는 언제든 공격 가능하고 공격 중 특별 무적·취약·경직 상태를 받지 않는다.

패턴상황 기반 선택예고·발동
방사형 (RADIAL)플레이어와 거리 235 미만몸체 회전·팽창 예고 후 꽃잎형 18발·버섯형 14발 원형 탄막 × 최대 2회, 변형으로 발수·회전 차이

보스 패턴 하나씩만 순차 실행하며, 소환수는 기본적으로 3기 내외, 동시 최대 4기, 제한시간 후 소멸하고 보스가 죽으면 제거된다. 상태는 BOSS_RECOVER / BOSS_WINDUP / BOSS_LOCK / BOSS_EXEC / BOSS_CHARGE / BOSS_RECOIL를 사용한다. 추적 예고 중 몸체 방향은 매 틱 갱신되며 LOCK 시작 뒤 고정된다. 서로 다른 패턴 사이 보스가 이동 방식을 바꾸며, 원거리 패턴은 거리를 조절한다.

보스 장애물 충돌: 고속 CHARGE 중 정적 장애물과 실제 충돌하면 장애물을 제거하고 파편 VFX를 보여 준다. 보스는 뒤쪽 반동으로 튕겨 나가고 BOSS_RECOIL 1,000ms 후 새 예고부터 CHARGE를 재시도한다. 반동 중 보스 방어력 변화는 없다. 탄막은 장애물에 막혀 소멸하고, 보스 몸체 접촉은 구르기 탄환 무적과 무관하게 피해를 준다.

테마 보스는 FAN·RADIAL·CHARGE·SUMMON 공통 패턴을 상황에 따라 고른다. 소환 패턴에는 동시 개체 수 제한과 유효 수명이 있고, 재등장 때 시드에 따른 변형이 적용된다. 피격으로 패턴을 끊는 추가 경직·체력별 2페이즈는 구현 범위 밖이다.

13. 스테이지·랜덤 다각형 맵

스테이지마다 반지름을 늘려 6~10각형 외곽을 만들고 내부에 테마별 조합 레시피로 볼록 다각형 장애물을 배치한다. 회피 공간과 보스 탄막 차단을 위해 스폰 위치·장애물 겹침을 검사한다. 내부 지형은 Bodies.polygon, 바깥 경계는 각 변을 따라 회전한 정적 사각형 벽이다.

radius = min(maxRadius, worldRadius × (1 + radiusGrowth × sqrt(stageIndex - 1)))
sides = 6 + floor(random × 5) // 6~10
outerRadius = radius × (0.88 + random × 0.22)
obstacleBudget = clamp(round(area / 100000 × obstaclePer100k), 4, maxObstacles)
playableArea ≈ polygonArea - sum(π × obstacleRadius²)
targetEnemies = clamp(round(playableArea / 100000 × enemyDensityPer100k), 5, maxEnemies)
killTarget = initialKills + (stageIndex - 1) × killsPerStage

테마/지형/보스 변형 선택은 스테이지 번호로 결정되는 재현 가능한 정수 시드를 사용한다. 자세한 현행 생성 계약은 24절을 기준으로 한다. 과거 초기 보스 3패턴·반지름 고정 공식은 24절의 생성기로 교체됐다. 맵 난수는 스테이지 번호를 조합한 결정적 정수 PRNG(LCG)로 초기화한다. 설치하는 물체·적과 기타 확률 이벤트는 동일한 게임 난수 함수를 사용한다. 스테이지 시작 시 플레이어를 중앙으로 돌려보내고, 공격·연격·에너지·구르기 자원을 초기화한다. 일반전 시작 적 수와 사망 후 보충 목표는 이동 가능 면적 기준의 일정 밀도를 따른다.

검증 기준: 같은 시드·카메라·유닛 배치에서 수정 전후를 비교한다. 화원·균사 동굴 × 일반전·보스전 × 모바일·PC에서 플레이어와 적/조준선/탄막이 장식보다 먼저 읽히는지 확인한다. 배경 단순화만으로 모든 대비를 해결했다고 주장하지 않고, 실제 게임 동일 크기의 장면을 확인한다.

기존 [BLOOM 파티클 연구소](https://github.com/byh-playground/bloom-reference/blob/main/labs/particles.html)의 dash, sparks, shockwave, chain, lightning, flame, embers, focus_brackets, damage_number, level_up 등이 참고 효과다. 현재 게임은 연구소의 전체 BloomEffects 런타임을 직접 연결한 상태는 아니다. 실제 게임에서 사용되는 효과는 Renderer2D 도형·파티클 기반으로 구현됐다. 화염은 연구소의 flame·embers 설계를 참고해 폭이 있는 불꽃 면, 좁아지는 화염 끝, 짧은 상승 불씨로 구현하며, 적 간 전염은 접촉 순간의 고정된 두 점에서 짧은 불씨만 이동한다. 효과는 물리 판정에 관여하지 않으며 불꽃의 기하 범위·수명·전염 궤적은 명시적으로 제한한다.

전투 숫자는 표시 단계에서만 정리한다. 10 이상은 정수, 1 이상은 소수 첫째 자리, 1 미만은 소수 둘째 자리까지 표시한다(매우 작은 양수는 <0.01). 충돌 피해·화상 DPS·체력 회복의 실제 계산값은 반올림하지 않는다.

최적화: 파티클 링버퍼 상한 particles.capacity, 링 최대 26개, 전기 아크 최대 24개, 부유 숫자 최대 24개. 효과는 시뮬레이션 HP·넉백·타겟 정책을 바꾸면 안 된다.

24. 영구 동행 · 알 · 합성

보스 처치마다 같은 보스 계열 알 1개를 영구 보유한다. 보유 수는 제한하지 않는다. 기본 동행 1칸에 슬롯 투자 4회로 최대 5칸이며 알과 펫이 같은 칸을 쓴다. 장착 알은 플레이어·펫의 모든 실제 처치마다 각각 +1, 30처치에 같은 UID·슬롯의 Common 펫으로 바뀐다. 예비 알은 진행하지 않는다.

펫은 접근 → 준비 → 물리 돌진 → 충돌 → 반동 → 재접근한다. 기본 피해 = 펫 공격력 × 충돌 직전 상대 접근 속도 ÷ 1600, 대상 방어를 공통 공식으로 적용한다. 가만히 겹친 몸은 펫에 피해를 주지 않으며 적 돌진과 실제 투사체는 피해를 준다. 펫 사망은 보유를 잃지 않고 3초 뒤 플레이어 근처에 최대 HP로 복귀한다. 수치는 Config의 측정 추천값이며 부활 3000ms는 확정 규칙이다.

Rare부터 꽃잎은 부채 탄막, 버섯은 탄성 반동·실제 피해 비례 근거리 회복을 얻는다. Legendary부터 원형 탄막을 더한다. 모든 등급은 기본 물리 공격을 유지한다. 등급별 체력·공격력 ×1.8, 크기·범위 ×1.05를 적용한다.

같은 종·등급 5마리 합성의 성공률은 Common→Mythic 순 64/32/16/8/4%. 성공은 5마리를 상위 1마리로 바꾸며 실패는 1~4마리를 균등 소모한다. 잠금만 보호하고 장착 여부는 보호하지 않는다. 예비 재료를 먼저 사용하며 연속 합성도 선택한 등급만 처리한다. 알·Mythic은 재료가 아니다. 보유·잠금·편성·부화 진행·슬롯 투자는 로컬 저장되어 사망·재시작에 유지된다.

24. 절차적 생성·보스 시스템 풀 (v0.10.0)

콘텐츠를 개별 코드로 추가하지 않는다. THEME_POOL 정의는 테마별 최초 등장 스테이지·출현 가중치·색상·지형 연산 레시피·외형·보스 타입만 소유한다. 보스는 BOSS_POOL 정의의 외형 프리셋·행동 풀 참조·소환수·변형률을 조합한다. 신규 테마는 정의 등록 후 최초 등장 보장과 이후 시드 기반 랜덤 후보에 자동 편입한다.

스테이지 크기와 평균 밀도

radius = min(maxRadius, worldRadius * (1 + radiusGrowth * sqrt(stageIndex - 1)))
outerBoundary = seeded convex 6..10-gon (vertex radius jitter ±~12%)
obstacleBudget = clamp(round(area / 100000 * obstaclePer100k), 4, maxObstacles)
playableArea ≈ polygonArea - sum(π * obstacleRadius²)
targetConcurrentEnemies = clamp(round(playableArea / 100000 * enemyDensityPer100k), 5, maxEnemies)
waveKillTarget = initialKills + (stageIndex - 1) * killsPerStage
// Do not mistake TARGET CONCURRENT population for required wave kills.

생성 파이프라인·검증

1. 스테이지 번호로 시드 고정 → 2. 해금 테마 선택(최초 등장 우선) → 3. 반지름 확대·6~10각형 외곽 생성 → 4. 선택된 지형 연산을 한 풀에서 조합 → 5. 출발 안전지대·장애물 중첩·통로 폭 제한 → 6. 굵은 격자 Flood-fill로 자유 공간 연결성 검증(미달 시 장애물 제거) → 7. 이동 가능 면적 기준 동시 적 밀도 계산 → 8. 적 최소 거리 배치 → 9. Matter.js 정적 장애물과 테마 색·장식 렌더링. 맵은 스테이지마다 새로 생성하며 기존 맵을 외부 확장하지 않는다.

공동/통로는 정적 다각형 장애물 사이의 개방 공간과 예약 통로로 표현한다. 완전한 오목 다각형 동굴 생성/내비메시가 아니다. 생성된 장애물이 플레이어·보스 충돌 및 탄막 차폐에 영향을 준다. 시드·테마·연산·실제 유효 공간은 진단 상태에서 재현 가능하다.

보스 행동 풀 공통 상태·계약

RECOVER -> choosePattern(situation, availableSummons) -> WINDUP(tracking)
  -> LOCK(freezeDirection) -> EXEC(FAN/RADIAL/SUMMON) or CHARGE -> RECOVER
CHARGE hits obstacle -> removeObstacle -> physical RECOIL(1000ms)
  -> WINDUP(CHARGE) again
SUMMON -> create units from shared enemy factory (type, ttl, owner, cap)
  -> minions may be killed, or expire with no kill/level reward
boss dies -> clear all owned summons -> CLEAR -> new stage/theme/map

보스 행동은 항상 패턴 하나씩 실행한다. 현재 등록된 원형 탄막, 부채꼴 탄막, 직선 돌진, 소환은 BOSS_PATTERNS 풀의 공통 구현이다. 보스별 외형 함수는 BOSS_VISUALS 풀을 사용하고, WINDUP과 LOCK 신호를 외형이 읽어 몸체 변화로 패턴을 예고한다. 소환수는 동일한 물리·속성·체력 컴포넌트를 사용하며, 일정 수명 후 HP 보상 없이 소멸한다. 소환형 패턴일 때만 보스 단독전 규칙에 예외를 둔다.

테마를 늘리는 계약

THEME_POOL에 unlockStage, layouts(공통 MAP_OPERATORS 함수들의 이름과 비율), obstacle, decoration, colors, boss를 등록하고, 새 보스 외형이 필요할 때 BOSS_VISUALS와 BOSS_POOL에 선언적으로 추가한다. 등록된 최초 등장 스테이지는 무조건 해당 테마를 쓰고 이후에는 해금된 테마만 랜덤 선택한다. 별도의 switch(stageIndex)나 스테이지별 구현 파일이 필요하지 않다.

조작 · 물리 실험

기본 능력치 · 8종 설정 열기

기본 능력치 8종만 유지합니다. 방어 관통은 대상의 방어력이 있을 때 적용됩니다. 잔상 속도·발사 준비·자동 연격은 각각 기본 물리 설정과 테크트리에서 관리합니다.
