# 시전 동선과 런타임 비용 검증

## 변경 경계

`90ea00b` → `09d7a08`은 결과가 같은 성능 리팩토링이다. 몹·펫·소환수의 목표 선택과 회복 대상 선택에서 임시 배열 및 정렬을 제거했다. 동률은 기존 월드 순서를 유지한다. 공격 도중 생성·죽음의 경계가 달라지지 않도록 `world.targets()` 스냅샷은 유지했다.

이후 v0.20.0은 사용자가 요청한 **의도적인 스킬 동선 변경**이다. 레이저처럼 실제 플레이어 본체가 이동하고 준비한 뒤 시전하고 돌아온다. 기존 `UltimateRunner`와 각 스킬의 `sequence`를 확장했으며, 게임 고유 안무를 GameKit에 추가하지 않았다. 본게임·프리뷰·28초 소개는 같은 시전자, 물리, 공격, VFX, 사운드와 카메라를 사용한다.

## 시전형 스킬 전체

단위는 ms이며 기존 timeScale·히트스톱은 별도로 적용된다. `smooth`는 smoothstep, `smoother`는 smootherstep, `outCubic`은 cubic ease-out이다. 시전 공격의 계수·횟수·반경·탄 수는 유지했다.

| 스킬 | 이동 위치 / 시간 | 준비 | 시전 | 복귀 / 이징 |
|---|---|---:|---:|---|
| iceGarden | 대상 앞 최소 110px 간격, 최대 64px 접근 / 240 | 300 | 180 | 260 / smoother |
| lightningChain | 반대 측면 58px / 200 | 220 | 280 | 240 / outCubic |
| fireSeed | 후방 64px / 260 | 300 | 600 | 300 / smoother |
| acidFountain | 측면 64px / 240 | 280 | 220 | 280 / smooth |
| laserBloom | 측면 78px / 220 | 600 | 800 + 반동 130 | 240 / smooth |
| storm | 측면 64px / 240 | 280 | 준비 위치 주변 공전 880 | 260 / smooth |
| chainDrive | 후방 60px / 220 | 220 | 3회 돌진 90 + 타격 유지 75 | 지나온 위치를 역순으로 420 / smooth |
| elasticBlast | 대상 앞 최소 95px 간격, 최대 70px 접근 / 260 | 400 | 420 | 320 / smoother |

적중형 패시브(coldTouch, freezeTouch, iceShatter, acidTouch, acidPool, acidSpread 등)는 타격에 부착되는 효과다. 별도 시전·탄약 소모·자동 스킬로 바꾸지 않았다. 몹·펫의 고유 능력도 플레이어 자동 스킬과 다른 소유권을 유지한다.

## 안전·콤보·생명주기

- 시전 위치가 막히거나 너무 가까우면 정해진 순서로 안전한 대체 방향을 검사한다. 시전 스스로 사거리 밖으로 이동하지 않는다. RNG 추가 없음.
- 이동은 기존 Matter 속도 적용을 사용한다. 매 tick 실제 본체 위치에서 경계·장애물 경로를 검사한다. 새 무적이나 충돌 무시를 추가하지 않았다.
- 복귀는 실제 단계 시작 위치를 역순으로 거친다. 물리적으로 막힌 위치로 강제 스냅하지 않는다.
- 탄약·슬롯 순환·재사용 타수 조건은 그대로다. 시전 중 획득한 콤보를 화면에 유지하고 종료 때 한 번 소모한다. 시전 중에는 다시 발동할 수 없다.
- 준비 중 타겟 소실은 공격 없이 복귀한다. 이미 시전된 동작은 완료 후 복귀한다. 사망·스테이지 변경·폐기는 현재 위치에서 즉시 취소하여 새 월드나 사망 상태로 이동을 이어가지 않는다.
- 프리뷰 종료도 Runner 취소와 음원 정리를 수행한다. 단계 음원·대기 공격은 다음 실행에 남지 않는다.

## 실제 검증

Windows Edge 155 / ANGLE D3D11 / GTX 1660 Ti에서 실제 DOM·Canvas WebGL 경로로 실행했다. 단일 시나리오 180초 상한을 적용했다.

- 시전형 8개 각각 두 번 실행: 단계 순서, 동률 포함 결정론, 콤보 유지, 정상 종료, 빈 공간에서 원점 오차 0, 저장 쓰기 0, dispose 뒤 RAF 0.
- 8개 × 타겟 소실·사망·스테이지 종료·폐기·장애물·경계 = 48건 통과. 타겟 소실은 피해 0으로 복귀. 사망·스테이지 변경은 즉시 정리.
- 8개 × 최대 사거리·근접 대상 = 16건 통과. 준비 이동 때문에 스스로 취소되는 경우 없음.
- 시전 확정 후 타겟 소실 8건도 추가 통과: 추가 피해 없이 시전 마무리·복귀, 자원 정리.
- 대표 프리뷰 7개와 28초 소개를 각각 동일 Seed로 두 번 끝까지 실행: 시뮬레이션 상태·피해·대상 상태·소개 메트릭 일치, 저장 쓰기 0. 약 23.8초에 검사 완료.
- 실제 UI 390px·1280px: 직접 진입/F5/뒤·앞 이동, 프리뷰 일시정지·재개·재시작·닫기/포커스, 소개 재시작·닫기, 전투 중 설정 복귀, 저장·구매 상태 보존 통과(9.1초).
- 실제 렌더 스크린샷 32장을 단계별로 확인했다. 게임별 기존 이펙트와 시전자 이동이 함께 보인다.
- 일반 전투의 Space 18회와 WASD 회피를 1,080 tick 실행: 기존 main과 게임 상태·저장 쓰기 일치. 실제 벽시계 기반 카메라 상태는 이 결정론 비교에서 제외했다.

경계 주입 검사는 다각형 안쪽 35px에 배치하여 두꺼운 물리 벽과 접촉할 수 있는 조건도 포함한다. 그 경우 물리적으로 도달 가능한 위치에서 멈추며, 충돌체 내부 원점으로 강제 복귀하지 않는다. 주입용 훅과 임시 검사 코드는 배포 코드에 포함하지 않았다.

## 비용 비교

리팩토링 집중 검사: 14개 후보를 15,000번 선택한 5회 중앙값. 몹 29.49→7.42ms, 펫 28.63→9.77ms, 회복 7.01→5.03ms. 소환수는 원래 단일 순회여서 8.84→8.84ms. 이는 합성 CPU 검사이며 게임 FPS 개선 수치가 아니다.

실제 소개 측정: 390×844, 1,680 고정 tick, 준비 1회 + 교대 실행 3회 중앙값. 서로 다른 측정 세션의 절대값은 직접 비교하지 않는다.

| 비교 | simulation CPU | render 제출 CPU | 초기화 | 전체 실행 CPU |
|---|---:|---:|---:|---:|
| 리팩토링 이전 → 이후 | 216.4→218.5ms | 2257.7→2262.3ms | 172.4→169.4ms | 2482.7→2489.4ms |
| 연출 추가 이전 → 이후 | 236.8→224.9ms | 2447.7→2303.2ms | 169.9→170.9ms | 2719.6→2537.9ms |

연출 비교 전체 측정 범위는 이전 2495.7–2722.7ms, 이후 2474.8–2700.9ms로 겹친다. 전체 게임 성능 향상·악화를 단정하지 않는다. 초기화에는 CDN 로딩/캐시 변동이 있다. GPU 실행 시간은 측정하지 않았으며 render CPU를 GPU 시간으로 해석하지 않는다. Android 실기기와 Safari는 미검증이다.

## 모듈 대조 결과

실제 사용 중인 rendering/input/simloop/camera는 기존 정확한 dist 핀을 유지했다. 새 rendering 번들은 사용하지 않는 mesh API로 28,020B, simloop는 사용하지 않는 예측 입력 등으로 14,229B 늘어난다. Renderer2D 구현은 동일하고 input/camera는 동일 바이트다. audio는 동일 SHA-256을 확인하고 Navigation/Scenario와 같은 dist `159746f50e819fdc9e8e3b9df102b542f7335f6d`로 핀만 통합했다.

플레이어의 7개 포즈 필드에 별도 interpolation 런타임을 추가하지 않았다. 롤백이 없는 로컬 게임에 presentation-events 확인 저널도 추가하지 않았다. `Unit`의 controller 소유, 종별 표현 공유, capability 조합은 유지했다.
