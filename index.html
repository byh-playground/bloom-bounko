1. 게임 개요와 설계 목표

BOUNKO는 블룸 세계관의 탑다운 2D 물리 액션 게임이다. 공격 버튼을 두 번 눌러 적에게 돌진하고, 전장을 탭하거나 WASD를 눌러 구르며 피한다. 멀리서 빠르게 충돌할수록 공격이 강해진다. 조작감 자체의 재미를 우선하며 성장과 이펙트는 이 흐름을 돕는다.

먼저 알아야 할 체력 규칙
① 수동 잔상 발사는 기본 2발의 공격 탄을 쓰고 1,500ms마다 1발씩 순차 장전한다. HP는 쓰지 않는다. 메아리와 자동 연격의 새 잔상도 같은 탄 1개를 쓴다. 이미 만든 잔상으로 돌진은 무료다.
② 평상 몸 접촉 피해는 0이다. 준비를 마친 돌진·근접·광선·탄환 등 명시적 공격에 맞으면 피해를 입는다.
③ 흡혈은 기본 0%이며 투자 후 실제 HP 피해 × 흡혈률만 회복한다. 시작 최대 HP는 200, 단계 전환으로는 회복하지 않는다.
④ 공격 버튼은 잔상 발사 → 돌진, 전장 탭과 WASD는 회피 구르기다.
모바일 우선탑다운Matter.js 물리Bloom GameKit랜덤 다각형 스테이지보스 탄막영구 테크트리
이 위키는 현재 단일 HTML 프로토타입의 실제 기본 설정과 동작을 설명한다. 테크트리·수치 표는 HTML 안의 런타임 Definition에서 생성한다. 이는 정식 출시 계획이 아니라 현재 실행 중인 프로토타입의 구현 기준이다.

지면 보상·자석: 피해로 확정된 적 처치의 기존 성장과 알을 사망 위치의 작은 드롭으로 남긴다. 성장 1개는 기존 처치 1회의 레벨 진척이며 새 돈이나 자원이 아니다. 일반/소환 5%·보스10% 알은 사망 때 한 번 추첨하고 회수 때 다시 추첨하지 않는다. 처치 사실·스테이지 목표와 장착 알의 30처치 부화는 사망 때 기록하며, 성장 레벨과 새 알 소유권은 회수 때만 지급한다. 기본 자석 반경은 현재 플레이어 지름 ×2.5(기본80px)이며, 자석 범위 투자당 기본 대비 +10%(80→88→96px)다. 범위 안에서 가속해 플레이어 방향으로 끌려오고 몸의 XYZ 접촉에 도착해야 한 번 회수된다. 드롭은 펫·공전 탄과 달리 지면에 있으며 몸체를 밀거나 피해를 주지 않는다. 근접 동종 보상은 수량을 합치고 최대128개 표현 객체를 재사용한다. 끌림은 적 목록을 검색하지 않으며 회수 숫자·알 강조·소리는 짧은 간격으로 묶는다.

클리어 회수: 일반·보스 클리어 후 1,500ms 동안 자석의 유효 범위를 맵 전체로 넓힌다. 기존 가속·XYZ 도착 접촉으로 실제 회수한 성장과 알만 지급한다. 시간 종료 시 회수 여부와 무관하게 남은 드롭을 삭제하고 저장의 미회수 목록도 비운 뒤 다음 단계로 넘어간다. 자동 지급이나 단계 간 보존은 없다. 클리어 이외의 사망·대기·재시작·새로고침은 기존 미회수 저장과 새 판의 지면 복구를 유지한다. 회수 목록 제거와 성장/알 소유권은 같은 저장 스냅샷에 담는다.

장착 알 추종: 바깥 장착 알은 공통 동행 대기 위치를 따라 시간 기반 임계 감쇠 스프링으로 느슨하게 추종한다. 이동 방향 뒤로 목표가 기울고 급회전에는 기존 속도를 이어 곡선으로 따라붙으며 정지하면 작은 높이로 부유한다. 안쪽 탄의 정밀 공전·지면 드롭과 구분된다. 단계/재시작과 큰 순간이동에서는 위치·추종 속도를 정리하며 부화 진척·슬롯·전투 펫 AI는 유지한다.

설계 불변 조건: 첫 공격은 플레이어 입력으로 시작하며, 차지율은 초기 충격량과 비행 가속만 결정한다. 기본 직접 피해는 실제 충돌 접근 속도로 결정한다. 잔상 조준, 공격용 물리 돌진, 이동용 회피 구르기는 별도 행동이다. 표현 파티클은 HP나 시뮬레이션을 수정하지 않는다.

5. 잔상·차지·골든타임

잔상은 플레이어 본체와 별개의 경량 객체이며 등속이 아니라 로켓형 가속을 사용한다. 적 자동 조준 시 잔상이 이동하는 적을 향해 방향을 갱신하며, 본체 돌진은 발동 순간 결정된 방향을 사용한다. 잔상 충돌은 해당 틱의 적 이동량까지 고려한 상대 선분 검사로 통과 누락을 줄인다.

shadow.speed += shadow.acceleration * dt
shadow.pos += normalize(target - shadow.pos) * shadow.speed * dt
remainingGap = max(0, distance(shadow, currentEnemy) - enemyRadius - 6)
charge = clamp(1 - remainingGap / initialGap, 0, 1)

공격 탄은 기본 2발, 1,500ms/발이며 공격·돌진·명중 회복·히트스톱 중에도 실제 틱 시간으로 순차 장전한다. 「잔상 비축 I/II」는 기본 대비 +50%/+100%로 3/4발이 되며 증가분은 즉시 지급한다. 「빠른 장전 I/II」는 기본 대비 −20%/−40%로 1,200/900ms가 되며 진행 중 장전 비율을 보존한다. 각 1 강화, I은 선행 없음, II는 같은 I만 요구한다. 수동·메아리·자동 연격 모두 실제 새 잔상 생성에만 1발을 쓴다. 0발에서도 기존 잔상 돌진은 가능하며, 새 잔상을 만들 수 없으면 자동 연결이 끝나고 장전만으로 다시 시작하지 않는다.

작은 청록 잔상 조각은 캐릭터 가까운 일정한 궤도를 공전한다. 다음 한 발만 본체 중심에서 궤도로 이동하며 자라나고, 충전 완료된 조각은 궤도에 남는다. 탄에는 접촉 공격이 없다. 아래 청록 막대는 별도 이동 충전이며 관성·포자는 실제 발동 VFX로 확인한다. 동료는 대기 시 더 바깥에 서지만 추적·공격 범위는 같다.

잔상 접촉은 피해를 주지 않고 적에게 물리 충격을 가한다. 기본 설정에서는 개방된 공간의 표준 적이 약 100 월드 단위 밀려나는 체감을 목표로 한다. shadow.contactPushSpeed=300은 적 질량을 고려한 초기 반동 속도(px/s)이고, shadow.contactPushControlMs=500 동안 추적 AI의 이동 보정이 실제 Matter.js 반동을 지우지 않게 한다. 기존 접근 속도가 있으면 방향 성분을 보정한 충격량(enemy.mass × max(0, speed - dot(velocity, direction)))만 주며, 좌표를 순간이동시키지 않는다. 장애물·다른 유닛과의 실제 충돌, 동작 중인 공격 패턴, 공기 저항에 따라 이동 거리는 달라질 수 있다. 보스는 공격 예고·실행 타이머를 멈추지 않는다. 적과 붙어 있어도 잔상 발사 자체를 막지 않는다. 단, 돌진은 플레이어와 현재 잔상 사이 거리가 shadow.minDashDistance 이상이어야 하며 너무 가까운 조준선은 빨간색으로 나타난다. 실제 수동 발사 성공 시에만 탄 1발을 쓴다. 실패한 발사·기존 잔상으로 돌진은 추가 탄을 쓰지 않는다.

차지 기준은 잔상이 이동한 누적거리가 아니라 현재 목표 표면까지 남은 거리이다. 적이 움직이면 매 물리 틱 새 거리를 반영한다. 빈 공간을 수동 잔상 발사하는 과거 기능은 현재 조작에서 제거되었지만, 내부 목적지 개념은 남아 있다.

잔상 접촉 순간 GOLDEN 상태로 들어가 차지율 100%를 제공하고 50ms 히트스탑을 적용한다. 이후 150ms COYOTE 창에는 차지율이 기본 94%에서 70%로 감소한다. 접근 말기 80% 차지부터 시뮬레이션 시간 비율 0.32의 불릿타임을 사용한다. 100% 타이밍은 최대 피해 보증이 아니다. 피해는 실제 충돌 속도가 결정한다.

VFX: 정상 거리 초록 조준 레이저 / 너무 가까운 적은 빨간 조준 레이저(발사와 밀어내기는 가능), 대상 주위 4방향 수축 에임, 잔상→표면 남은 거리 연결선, GOLDEN 금색, COYOTE 푸른 잔광. 글자 안내보다 위치·거리의 변화로 타이밍을 읽게 한다.

6. Matter.js 물리와 좌표·시간

좌표는 +X 오른쪽, +Y 아래인 월드 픽셀 기준이며 Z는 지면 위 발밑 높이다. 몸체의 수직 구간은 feetZ부터 feetZ + height까지다. 월드 크기, 질량·반발 계수·최대 속도 등은 아래 원본 Config 표를 따른다. 중력은 0. Matter.js 0.20.0의 Engine.update를 60 TPS 고정 스텝으로 실행한다.

speedOf(body) = Body.getVelocity(body) × 60       // world pixel/second
setSpeed(body, v) = Body.setVelocity(body, v / 60)
applyImpulse(body, J): velocity += J / body.mass
Body.applyForce(body, body.position, direction × body.mass × acceleration / 1e6)

잔상 무피해 밀어내기 검증: 스카우트(질량 4.6)·중장갑(질량 8.2)·보스(기본 질량 36)를 대상으로 열린 공간에서 0.5초 후 약 100 월드 단위 이동을 목표로 한다. AI 이동 보정을 500ms 동안만 중지하되 경고·패턴 타이머를 유지한다. 장애물 앞에서는 실제 충돌에 의해 이동 거리가 제한되어야 하며 잔상 자체로 HP가 감소하거나 플레이어가 순간이동하면 안 된다.

실제 구현 단위 경계: 위 변환식은 게임 내부 월드 픽셀/초 단위를 Matter의 기본 틱 속도로 변환하는 어댑터다. 일반 이동의 위치·속도, 충돌 응답, 반동은 Matter 소유. 피해·피격 무적·HP·속성 상태는 게임 소유.

고속 충돌: Matter의 이산 물리로 빠른 돌진이 적을 관통할 수 있으므로, 이전 틱 플레이어/적 위치에서 상대 궤적의 원 교차를 계산해 가장 빠른 접촉 하나를 보완한다. 장애물과 탄막은 Matter 센서·정적 물체 충돌로 처리한다.

7. 공격·방어·회복 공식

closingSpeed = max(0, dot(playerPreVelocity - enemyPreVelocity, contactNormal))
rawDamage = isAttackingDash ? attackPower * closingSpeed / referenceSpeed : 0
criticalRaw = rawDamage * (isCritical ? criticalDamage : 1)
effectiveArmor = max(0, enemyArmor * (1 - armorPenPercent) - armorPenFlat)
outgoingDamage = round(criticalRaw * 100 / (100 + effectiveArmor))
inflicted = min(enemyRemainingHP, max(0, outgoingDamage))
heal = min(effectiveHPDamage * attacker.lifeSteal, attackerMaxHP - attackerHP) // base lifeSteal = 0

충전율·이동거리의 피해 배율은 없다. 차지율은 초기 Impulse와 지속 가속만 바꾸므로 장거리 정타는 비행 중 실제 충돌 속도가 상승하는 방식으로 보상받는다. 공격마다 치명타는 criticalChance 확률로 판정하고 기본 2배(200%)에 투자당 6%p가 가산된 criticalDamage를 곱한다. 관통은 퍼센트 관통 후 고정 관통 순으로 적용한다.

체력의 기본 흐름: 시작 최대 HP는 200이며 기존 최대 체력 투자당 기본값의 +6%를 유지한다. 수동·메아리·자동 연격의 새 잔상은 공통 공격 탄 1발을 쓴다. HP 비용은 없으며 이미 만든 잔상으로 수동·자동 돌진은 무료다. 평상 몸 접촉 피해는 0이며, 준비를 마친 돌진·도약·근접·광선·탄환·폭발만 공통 피해 수신에 전달된다. 플레이어와 동행의 돌진은 같은 공격력 × 상대 접근속도 / 1600 공식을 사용한다. 단계 전환은 현재 HP를 유지하고 새 판 시작만 최대 HP로 초기화한다.

흡혈: 기본 0%, 투자당 +2%p, 최대 15회·30%다. 방어·보호 시간·반올림을 적용하고 실제 줄어든 HP만 기준으로 하므로 과잉 피해는 회복을 늘리지 않는다. 직접·범위·화상·투사체 공격이 같은 수신 규칙을 사용하며 실제 공격자가 회복한다. 소멸한 투사체 소유자는 회복하지 않는다. 체력 재생과 치유 동행의 회복은 별도로 유지하며 최대 HP까지만 회복한다. 모든 공격의 같은 틱 피해와 흡혈을 반영한 뒤 HP가 0 이하면 게임을 종료하며 사망 효과는 한 번만 처리한다.

화염 지속 피해도 흡혈률이 0%면 회복하지 않고, 투자한 흡혈률만 적용한다. 감속·충돌 등 시뮬레이션 결과 없는 단순 VFX만으로는 피해·회복이 발생하지 않는다.

8. 돌진 가속·비행·회복

돌진 시작 시 차지율을 부드럽게 매핑하여 최소/최대 초기 속도 변화를 계산하고, 그 결과의 크기에 비례하는 지속 가속을 설정한다. 발동 순간 목표 방향이 고정되고 기존 횡관성만 제거된다. 같은 속도로 충돌하면 첫 차지율이 달라도 같은 피해를 입힌다.

chargeSmooth = charge² × (3 - 2 × charge)
deltaV = dash.minSpeed + (dash.maxSpeed - dash.minSpeed) × chargeSmooth
acceleration = dash.acceleration × deltaV / dash.maxSpeed
// add charge-based impulse once, then force each fixed tick
// normal collision or swept contact resolves hit; render trail does not change physics

기본 공격 피해 유효시간은 짧은 고정 대기시간(현재 400ms)으로 끊지 않는다. 원거리 돌진은 목표까지 비행·명중 또는 속도 소멸/수명 종료 판정으로 끝난다. 최대·최소 비행 시간과 목표 거리 여유시간은 Config의 dash.flight* 설정을 참조한다. 빗나가거나 멈춘 돌진은 최소 150ms 뒤 속도 700px/s 이하이면 끝나고, 고속일 때는 400ms까지 기다린다. 살아 있는 목표에 접근 중이면 비행 판정을 유지한다. 명중 뒤 RECOVER는 기존 100ms·거리 조건·최대 300ms를 사용한다. 이 자세 회복 중 다음 발사는 최대 450ms 예약할 수 있으며, 구르기로 공격을 취소할 수 있다. 첫 빗나감 때 작은 안내를 한 번 보여준다. 탄 장전과 자세 회복은 별도 상태다.

이동 구르기는 무료이며 공격 탄과 별도다. 이동 가지의 각 노드는 1 강화이고 자동 연격을 요구하지 않는다. 충전량 I → 명중 재충전, 충전 시간 I → 탄환 회피가 열리며 거리 가지는 독립이다. 모든 수치는 기본값 대비 누적 비율로 계산한다. 충전량은 2→3→4회이며 증가분을 해금 즉시 지급하고, 충전 시간은 500→400→300ms, 투사체 회피는 100→150ms다. 거리 증가는 이동 시간을 연장하지 않고 기존 추진력·감쇠 경로에 적용하므로 실제 거리는 관성·마찰·벽 충돌에 영향을 받는다.

명중 재충전은 실제 HP 피해를 준 공격 대시당 최초 명중 1회에 다음 이동 충전 진행도 20%를 더한다. 현재 1회 충전 시간을 기준으로 하므로 기본 100ms, 충전 시간 강화 후 80ms/60ms에 해당한다. DoT·포자·폭발의 반복 피해는 이 경로를 호출하지 않는다. 충전 완료를 넘긴 진행도는 다음 칸에 이어지며, 충전이 가득 찼으면 저장해 두지 않는다.

대시가 벽을 통과하거나 장애물을 무조건 무시하도록 위치를 직접 이동시키지 않는다. 구르기 속도는 충돌·마찰로 감소할 수 있으며 정면 방향 기준보다 역방향으로 강제 당기지 않도록 추가 속도 성분만 제거한다.

10. 메아리·자동 연격·도탄

준비 탄 하나가 현재 공전 위치에서 발사 방향으로 짧게 정렬한 뒤 같은 조각으로 날아간다. 수동·메아리·연격은 모두 기본 80ms 정렬을 거쳐 실제 잔상을 생성한다. 생성 순간 반대 방향 45px/s의 작은 물리 반동이 최대120ms 동안 감쇠(18/s)하고 몸이 짧게 눌렸다 돌아온다. 반동 성분은 전진 속도와 별도로 추적하고 실제 Matter 공기 저항을 함께 반영한다. 후속 돌진·구르기 전에 남은 반동을 정리하며, 실제 고체 충돌이나 속도 전체 교체 뒤에는 이전 반동을 복원하지 않는다. 탄 뒤 분출과90ms 꼬리, 기존 발사음이 같은 성공 이벤트에 연결된다. 발사 화면 흔들림은1.8 CSS px/85ms, 950px/s 이상 강한 명중은4px/150ms이고 가장 강한 남은 이벤트만 유지하며5px 상한을 둔다. HUD는 고정되고 카메라 변환과 입력 역변환이 같은 좌표를 사용한다. 정렬 전에 탄을 차감하거나 접촉을 판정하지 않으며, 구르기·사망·단계 전환으로 취소되면 발사되지 않는다.

새 잔상을 만들 때 공격 탄 1개, 이미 만들어진 잔상으로 돌진은 무료다. 수동·명중 후 메아리·연격의 다음 잔상 모두 같은 충전 정책을 사용한다. 실패한 생성은 소모하지 않는다. 공격 탄은 자연 장전으로만 회복한다.

「잔상 메아리」는 명중 뒤 다음 잔상을 자동 생성하며 돌진은 직접 입력한다. 「자동 연격」(2 강화)은 메아리를 선행으로, 수동 잔상 타이밍 50% 이상 실제 명중 + 다음 탄 보유 시 후속 잔상과 돌진까지 연결한다. 후속 명중은 같은 수동 타이밍을 다시 요구하지 않는다. 마지막 탄으로 생성한 잔상도 자동 돌진할 수 있다. 더 만들 탄이 없거나 대상이 사라지면 연결이 종료되고, 장전 완료만으로 자동 연격이 다시 시작하지 않는다.

if (newShadowActuallyCreated): ammo -= 1
// manual / echo / chain share this single creation policy
if (existingShadowDash): noAdditionalCost
if (manualHit && shadowTiming >= 0.50 && ammo > 0): chainActive = true
if (nextShadowCreationFails): chainActive = false
// no movement charge, hit refund or automatic restart after reload

자동 연격에는 같은 살아 있는 대상의 재공격이 포함된다. 도탄 연격은 기존 반경 내 다른 적을 선택하고 처치 후 추적은 죽은 대상 뒤 다른 적 선택을 허용한다. 전도 표식의 대상 선택 우선순위는 유지한다. 수동 예약이 성공하면 직접 조작이 우선하고, 실패한 예약 자체로 탄을 차감하지 않는다.

작은 공전 잔상 조각은 공격 탄, 캐릭터 아래 막대는 별도 회피 충전이다. 적 주변 조준선은 실제 잔상 타이밍을 표시한다. 콤보는 실제 HP를 감소시킨 명중만 센다. 삭제된 기술은 현재 저장 Definition에서 제외하여 해당 포인트를 한 번 환급하고 처치·유효 기술을 유지한다.

11. 일반 적 AI·타입

12. 보스 AI·탄막·예고

첫 보스는 고속 전투형이다. 보스전 진입 시 일반 적과 이전 탄막을 제거해 플레이어와 보스로 시작한다. 이후 공통 소환 패턴이 시작되면 제한된 수의 일시 소환수가 등장한다. 보스는 언제든 공격 가능하고 공격 중 특별 무적·취약·경직 상태를 받지 않는다.

테마 보스는 FAN·RADIAL·CHARGE·SUMMON 공통 패턴을 상황에 따라 고른다. 소환 패턴에는 동시 개체 수 제한과 유효 수명이 있고, 재등장 때 시드에 따른 변형이 적용된다. 피격으로 패턴을 끊는 추가 경직·체력별 2페이즈는 구현 범위 밖이다.

13. 스테이지·랜덤 다각형 맵

보스는 3·6·9…단계에 등장하고, 맵은 1~3·4~6·7~9…구간마다 반지름을 늘려 6~10각형 외곽을 만들고 내부에 테마별 조합 레시피로 볼록 다각형 장애물을 배치한다. 회피 공간과 보스 탄막 차단을 위해 스폰 위치·장애물 겹침을 검사한다. 내부 지형은 Bodies.polygon, 바깥 경계는 각 변을 따라 회전한 정적 사각형 벽이다.

mapTier = floor((stageIndex - 1) / mapEvery) // mapEvery = 3
radius = min(maxRadius, worldRadius × (1 + radiusGrowth × sqrt(mapTier)))
sides = 6 + floor(random × 5) // 6~10
outerRadius = radius × (0.88 + random × 0.22)
obstacleBudget = clamp(round(area / 100000 × obstaclePer100k), 4, maxObstacles)
playableArea ≈ polygonArea - sum(π × obstacleRadius²)
stage 1 targetEnemies = initialPopulation // 4
proportional = round((initialPopulation + (stageIndex - 1) × populationPerStage) × playableArea / firstPlayableArea)
stage 2+ targetEnemies = min(maxEnemies, max(previousPopulation + populationPerStage, proportional))
killTarget = initialKills + (stageIndex - 1) × killsPerStage

테마는 확장 구간의 시작에 선택하며 구간 안에서는 반경·테마·지형 seed가 같다. 일반 적 배치와 보스 변형은 각 단계 seed를 사용한다. 자세한 생성 계약은 26절을 따른다. 매 단계 시작에 플레이어를 중앙으로 돌려보내고 공격·연격·구르기 상태를 초기화한다. 공격 탄의 충전 진행은 유지한다. 동시 생존 적 목표는 첫 4마리에서 단계당 1과 첫 맵 대비 실제 플레이 면적 비율로 늘고, 다음 구간의 랜덤 형상이 작게 나와도 이전 목표보다 최소 1 늘린다(최대 82).

일반 단계는 처치 목표 달성으로 다음 단계에 넘어가고, 3의 배수 단계는 보스를 처치해야 넘어간다. 각 전이 뒤 현재 체력을 유지하며 4·7…단계에서 맵이 확장된다. 중앙의 STAGE 번호는 1,100ms 뒤 사라지고 입력·게임 틱을 막지 않는다. 보스 예고는 같은 배너의 더 높은 우선순위를 사용하며 별도 clear 문구는 중앙에 겹치지 않는다. 현재 구현은 완전 자유 형태·오목 다각형·내비메시 생성기를 제공하지 않는다. 아래 26절의 테마·보스 정의 자동 표와 생성 파이프라인을 현행 기준으로 사용한다.

회수한 처치 성장 3/8/15/24/35/48/... 개에서 레벨이 오른다. 실제 처치 기록·단계 목표와 장착 알 진척은 회수 전에 기록한다. 레벨당 강화 기회 1개를 지급해 기본 스탯 1회 투자 또는 테크 노드 1개를 선택한다. 명중·완벽 명중은 별도 성장 포인트를 지급하지 않는다. 기술별 비용은 기본적으로 1, 「자동 연격」은 기존 두 능력을 묶어 2 강화이며 선행 노드를 해금해야 한다. 무료 초기화는 투자한 능력치·기술을 모두 환불하지만 회수 성장·실제 처치 기록·레벨은 유지한다.

로컬 저장소 키는 bloom-impulse-progression-v3이며 {kills, defeats, unlocked, statLevels, companions:{inventory,slots,nextId}, pendingDrops:{pending}}를 보존한다. 알·펫 보유, 잠금, 알 진행, 편성과 슬롯 투자는 사망·재시작에도 유지한다. 현재 Definition에 없는 기술 ID와 선행 조건을 잃은 투자만 제외해 사용 포인트를 환불한다. 기존 누적 성장(저장 kills)·실제 처치(defeats)와 유효한 나머지 기술·스탯은 보존하며, 제거된 기술을 새 ID로 자동 변환하지 않는다. 치명타 확률 투자 없이 저장된 치명피해 투자는 같은 방식으로 환불한다. 이후 저장은 현행 Definition만 기록한다. 오래된 bloom-impulse-tech-v1과 bloom-impulse-progression-v2는 계속 사용하지 않는다.

기술 속성/선행관계의 정확한 목록은 아래 기술 Definition 전체 표를 기준으로 한다. 플레이어가 선택한 실제 구매 상태는 이 테이블의 원본이 아니다.

17. 기본 능력치·흡혈·투자량

공격·치명·관통·최대 HP·방어·재생·흡혈·동행 슬롯·자석 범위를 정의한 공통 성장 표를 사용한다. 흡혈은 기본 0%에서 별도 투자하며, 자동 탭 속도·회전속도·발사속도·탄환속도 성장은 없다. 게임의 자동화와 돌진은 기술·물리 설정이 소유한다.

증가 규칙: 상대값은 기본 수치 × (1 + 투자횟수 × 보너스), 확률류와 치명피해는 %p 가산, 고정 관통과 방어력은 기준 공격력 비례 절대량 증가, 체력 재생은 기준 최대 체력 대비 초당 회복량 증가. 확률·퍼센트 관통 상한은 95%다. 치명피해는 기본 200% + 투자횟수 × 6%p로 1회 206%, 2회 212%가 되며 현재 배율에 다시 곱하지 않는다. 치명타 확률에 1회 투자한 뒤 치명피해 구매가 열린다. 위 표의 현재 실제 값은 저장 투자와 구매를 반영한다.

낮음 · 분위기화원 꽃잎 조각, 동굴 버섯 장식, 바닥 격자·오브젝트 장식, 비전투 파티클저채도·저불투명도·감소된 밀도, 플레이어 주변에서 더 흐리게, 보스전에서 추가 감쇠. 조작에 필요한 위치·판정 정보는 담지 않는다.

기본 설정: 화원 장식 알파 배율 THEME_POOL.garden.visual.decorationOpacity=0.60, 색 포화도 배율 0.54. 균사 동굴은 각각 0.57, 0.54. 공통 장식 밀도는 기존 대비 0.84이다. 원색을 그대로 표시하지 않고 지면의 기준색·명도와 혼합해서 배경으로 물린다. 플레이어 중심 88 월드 단위 안은 장식 알파를 54%까지 낮추고, 다음 112 단위에 걸쳐 부드럽게 복귀한다. 보스전 장식 알파는 추가로 78%를 곱한다. 장애물은 별도의 중간 계층을 유지하여 항상 이동 불가 경계가 식별된다.

검증 기준: 같은 시드·카메라·유닛 배치에서 수정 전후를 비교한다. 화원·균사 동굴 × 일반전·보스전 × 모바일·PC에서 플레이어와 적/조준선/탄막이 장식보다 먼저 읽히는지 확인한다. 배경 단순화만으로 모든 대비를 해결했다고 주장하지 않고, 실제 게임 동일 크기의 장면을 확인한다.

참고: Riot Games · VALORANT Shaders and Gameplay Clarity, Material Design · Color Hierarchy, W3C · Contrast. WCAG의 텍스트 대비 수치는 게임 내 모든 장식에 강제로 대입하는 규칙이 아니라, 플레이 정보의 명암 가독성 설계에 참고한다.

기존 [BLOOM 파티클 연구소](https://github.com/byh-playground/bloom-reference/blob/main/labs/particles.html)의 dash, sparks, shockwave, chain, lightning, flame, embers, focus_brackets, damage_number, level_up 등이 참고 효과다. 현재 게임은 연구소의 전체 BloomEffects 런타임을 직접 연결한 상태는 아니다. 실제 게임에서 사용되는 효과는 Renderer2D 도형·파티클 기반으로 구현됐다. 화염은 연구소의 flame·embers 설계를 참고해 폭이 있는 불꽃 면, 좁아지는 화염 끝, 짧은 상승 불씨로 구현하며, 적 간 전염은 접촉 순간의 고정된 두 점에서 짧은 불씨만 이동한다. 효과는 물리 판정에 관여하지 않으며 불꽃의 기하 범위·수명·전염 궤적은 명시적으로 제한한다.

전투 숫자는 표시 단계에서만 정리한다. 10 이상은 정수, 1 이상은 소수 첫째 자리, 1 미만은 소수 둘째 자리까지 표시한다(매우 작은 양수는 <0.01). 충돌 피해·화상 DPS·체력 회복의 실제 계산값은 반올림하지 않는다.

최적화: 파티클 링버퍼 상한 particles.capacity, 링 최대 26개, 전기 아크 최대 24개, 부유 숫자 최대 24개. 효과는 시뮬레이션 HP·넉백·타겟 정책을 바꾸면 안 된다.

25. 영구 동행 · 알 · 합성

적에게 피해를 주어 처치하면 일반 적과 소환수는 5%, 보스는 10% 확률로 같은 종의 알 1개를 지면에 떨어뜨린다. 몸에 회수할 때 소유권을 얻는다. 사망 때 추첨은 한 번이며 회수 때 재추첨하지 않는다. 자폭 완료·소환 만료·스테이지 정리·동행 사망은 처치 보상이 없다. 장착한 모든 알은 직접 적중 처치와 그 적중에서 시작한 상태 피해 처치마다 +1이며 소환수도 포함한다. 30처치에 같은 소유 ID·슬롯·종의 Common으로 부화한다. 예비 알은 진행하지 않는다.

기본 1칸에서 슬롯 강화 4회로 최대 5칸이다. 기존 종 Common은 물리 충돌 돌진을 하고 Uncommon부터 원래 종의 능력을 해금한다. 신규 왕사슴·민들레·칼잎·가시창은 Common부터 각각 돌진·짧은 근접·휘두르기·단일 찌르기를 쓰며 이슬치유사는 Common부터 공격 없이 치유한다. 높은 등급은 기존 능력과 패턴을 성장시키며 Mythic은 완성 패턴을 사용한다. 보스 동행도 같은 능력과 소환수를 사용한다. 원래 보스에 없는 회복 능력을 추가하지 않는다. 동행은 쓰러지면 3초 뒤 최대 HP·새 능력 상태로 복귀한다. 플레이어의 기술·스탯·공격 탄을 복제하거나 소비하지 않는다.

적과 동행은 같은 Unit·능력·성체 그림을 사용한다. 목표·이동 의도는 컨트롤러, 색·그림·알의 색과 무늬는 외형 설정, 사망 후 보상·복귀는 각각의 사망 정책이 소유한다. 같은 진영의 충돌·투사체·광역 공격은 피해를 주지 않는다. 보스의 탄막 대기·소환 수는 소유 Unit마다 계산한다.

같은 종·등급 5마리를 합성한다. Common→Uncommon→Rare→Epic→Legendary→Mythic 성공률은 64/32/16/8/4%다. 성공은 5마리 소모·상위 1마리 생성, 실패는 1~4마리 균등 소모다. 명시적 잠금만 보호하고 장착 여부는 보호하지 않는다. 예비 재료를 먼저 사용하며 연속 합성도 선택한 등급만 처리한다. 알·Mythic은 재료가 아니다. 발견 전에는 알의 이름·상세를 숨기고 성체에서 온 색과 무늬만 단서로 보여준다. 첫 부화에서 이름·모습·대표 능력을 공개하며, 발견 기록은 합성 소모와 독립해 유지한다. 소유 ID·종 ID·등급·잠금·편성·부화 진행·발견은 같은 저장 키에 보존한다.

동행 크기·아군 표시: 같은 종 적의 기준 몸체 대비 Common 65% → Uncommon 72% → Rare 79% → Epic 86% → Legendary 93% → Mythic 100%다. 실제 6등급을 선형 정규화한 한 설정을 반지름·높이·몸 그림자·선택과 피격 판정에 함께 사용한다. 등급색 외곽선은 원래 종 몸체 실루엣을 따르며, 몸 색과 등급색이 가까울 때만 얇은 중립 대비선을 안쪽에 더한다. 아군 소환수는 소유자의 크기·등급색 표시 정책을 이어받는다. HP·피해·질량과 스킬 범위·투사체 성장 규칙은 유지한다.

카드 슬롯 조작: 보유한 펫·알 카드만 표시한다. 보유 카드 탭은 첫 빈칸에 장착하고 장착 슬롯 탭은 해제한다. 빈칸이 없으면 안내만 하며 자동 교체하지 않는다. 기본 1칸부터 강화로 최대 5칸이며 잠긴 칸은 해금 안내로 구별한다. 알의 종별 색·무늬, 부화 진척, 등급색과 같은 종·종류·등급의 보유 수를 함께 표시한다. 잠금은 합성 보호이며 장착 제한이 아니다.

26. 절차적 생성·보스 시스템 풀

콘텐츠를 개별 코드로 추가하지 않는다. THEME_POOL 정의는 테마별 최초 등장 스테이지·출현 가중치·색상·지형 연산 레시피·외형·보스 타입만 소유한다. 보스는 BOSS_POOL 정의의 외형 프리셋·행동 풀 참조·소환수·변형률을 조합한다. 신규 테마는 확장 구간 시작(1·4·7…)에 최초 등장하도록 정의하며 이후 구간의 시드 기반 후보에 편입한다.

3단계 보스·맵 구간과 동시 생존 수

bossStage = stageIndex % bossEvery == 0 // bossEvery = 3
mapTier = floor((stageIndex - 1) / mapEvery) // mapEvery = 3
mapStart = mapTier * mapEvery + 1
radius = min(maxRadius, worldRadius * (1 + radiusGrowth * sqrt(mapTier)))
outerBoundary = seeded convex 6..10-gon (vertex radius jitter ±~12%)
obstacleBudget = clamp(round(area / 100000 * obstaclePer100k), 4, maxObstacles)
playableArea ≈ polygonArea - sum(π * obstacleRadius²)
firstPlayableArea = stage 1 playableArea
proportional = round((initialPopulation + (stageIndex - 1) * populationPerStage) * playableArea / firstPlayableArea)
targetConcurrentEnemies = stageIndex == 1 ? initialPopulation : min(maxEnemies, max(previousPopulation + populationPerStage, proportional))
// initialPopulation=4, populationPerStage=1, maxEnemies=82
waveKillTarget = initialKills + (stageIndex - 1) * killsPerStage
// Do not mistake TARGET CONCURRENT population for required wave kills.

생성 파이프라인·검증

1. 확장 구간 시작 번호로 지형 seed 고정 → 2. 구간 테마 선택(최초 등장 우선) → 3. 구간 반경·6~10각형 외곽 생성 → 4. 선택된 지형 연산을 한 풀에서 조합 → 5. 출발 안전지대·장애물 중첩·통로 폭 제한 → 6. 굵은 격자 Flood-fill로 자유 공간 연결성 검증(미달 시 장애물 제거) → 7. 첫 면적 대비 비율·현재 단계로 동시 적 목표 계산 → 8. 적 최소 거리 배치 → 9. Matter.js 정적 장애물과 테마 색·장식 렌더링. 같은 구간은 동일한 지형 seed로 재생성하며 크기·테마·형상을 유지한다. 4단계에서 반경 550→671로 확장하며 균사 동굴을 처음 선택하고, 4~6 구간을 유지하므로 6단계에 버섯왕이 등장한다.

공동/통로는 정적 다각형 장애물 사이의 개방 공간과 예약 통로로 표현한다. 완전한 오목 다각형 동굴 생성/내비메시가 아니다. 생성된 장애물이 플레이어·보스 충돌 및 탄막 차폐에 영향을 준다. 시드·테마·연산·실제 유효 공간은 진단 상태에서 재현 가능하다.

보스 행동 풀 공통 상태·계약

RECOVER -> choosePattern(situation, availableSummons) -> WINDUP(tracking)
  -> LOCK(freezeDirection) -> EXEC(FAN/RADIAL/SUMMON) or CHARGE -> RECOVER
CHARGE hits obstacle -> removeObstacle -> physical RECOIL(1000ms)
  -> WINDUP(CHARGE) again
SUMMON -> create units from shared enemy factory (type, ttl, owner, cap)
  -> minions may be killed, or expire with no kill/level reward
normal wave goal -> CLEAR -> next stage (no boss)
3/6/9... wave goal -> BOSS_PENDING -> BOSS
boss dies -> growth/egg ground drop -> clear enemies/summons/projectiles -> CLEAR
  -> pending drops survive and are re-presented near the next stage spawn
next stage -> centered stage number; 4/7/10... expands map/theme segment

보스 행동은 항상 패턴 하나씩 실행한다. 현재 등록된 원형 탄막, 부채꼴 탄막, 직선 돌진, 소환은 BOSS_PATTERNS 풀의 공통 구현이다. 보스별 외형 함수는 BOSS_VISUALS 풀을 사용하고, WINDUP과 LOCK 신호를 외형이 읽어 몸체 변화로 패턴을 예고한다. 소환수는 동일한 물리·속성·체력 컴포넌트를 사용하며, 일정 수명 후 HP 보상 없이 소멸한다. 소환형 패턴일 때만 보스 단독전 규칙에 예외를 둔다.

테마를 늘리는 계약

THEME_POOL에 unlockStage, layouts(공통 MAP_OPERATORS 함수들의 이름과 비율), obstacle, decoration, colors, boss를 등록하고, 새 보스 외형이 필요할 때 BOSS_VISUALS와 BOSS_POOL에 선언적으로 추가한다. unlockStage는 확장 구간 시작 번호(1·4·7…)로 등록한다. 해당 구간에서 최초 테마를 보장하고 구간 내 테마를 유지하며, 이후 구간에서는 해금된 테마만 시드로 선택한다. 현재 화원은 1단계, 균사 동굴은 4단계 첫 해금이며 보스는 각각 3·6단계다. 별도의 switch(stageIndex)나 스테이지별 구현 파일이 필요하지 않다.

27. 네 적의 능력 조합과 수직 충돌

첫 웨이브는 기존 4마리 제한을 유지하며 그림자벼룩(rogue)·폭낭 콩벌레(pillbug)·가시열매(thornfruit)·다연발 봉선화(rocket)를 차례로 생성한다. 보충은 기존 일반 7종과 신규 5종의 가중치 풀에서 선택한다. 껍질벌레·수호버섯·마법사는 추가하지 않는다. 각 외형은 Rally 89ff07f의 분절 껍질과 폭낭, 열 개 가시, 네 씨방, 큰 뒷다리와 앞다리 도형·비율을 옮겼다.

enemies.js의 Rogue는 Unit + Leapable, Pillbug는 Unit + SelfDestructible, Thornfruit는 Unit + SpikeCounterable, Rocket은 Unit + ArcFireable이다. abilities.js의 mixin(Base, ...Mixins)·mixin(...Mixins)는 subclass factory를 함수 identity로 중복 제거한다. 생성 시 클래스가 조합되며 프레임마다 새 믹스인을 만들지 않는다. Unit은 몸체·스펙·spatial 데이터를 소유하고 각 능력은 leap, selfDestruct, spike, arcFire의 설정·상태·타이머·행동을 직접 소유한다. 능력 메서드는 명시적인 super 체인으로 공통 추적·생명주기와 연결된다.

벼룩: 320ms 예고 후 650ms, 최고 높이 90의 도약. 발사 때 고정한 목적지 표식과 현재 x/y 그림자는 별개다. 장애물·경계로 막힌 경로는 시작하지 않는다. 착지에는 별도 피해나 광역 공격이 없다. 실제 몸체 부피가 겹치는 접촉 경로만 피해를 준다. 콩벌레: 가까워지면 1,000ms 자폭 예고. 이 동안 처치하면 취소하며 사망 폭발은 없다. 살아서 완료하면 반경 96 폭발 후 퇴장한다. 가시열매: 550ms 준비 → 450ms 가시 활성 → 1,500ms 회복. 활성 시작에 방사 가시를 발사하고, 활성 중 살아남은 직접 타격에는 창당 한 번 반격한다. 준비·회복에도 공격 가능하며 상시 반사는 없다. 봉선화: 490ms 예고 후 150ms 간격 4발, 높이 88/96/100/92. 조준 위치를 고정하고 현재 탄 그림자와 고정 착탄 경고를 분리한다. 비행 중 몸체가 겹쳐도 폭발하지 않고 정해진 지점에 한 번만 착탄한다. 곡사 비행·수명은 같은 시뮬레이션 dt를 쓰므로 히트스톱·SHADOW 감속 중 일반 탄의 global-time 만료로 사라지지 않는다.

수직 부피: 플레이어 높이 32, 벼룩 30, 콩벌레·가시열매 38, 봉선화 42. 기존 적·펫은 실제 몸체 반지름의 2배, 일반 탄은 반지름의 2배, 잔상은 높이 14를 사용한다. Matter 몸체의 plugin.volume이 발밑 높이·이전 높이·높이·한 틱 이동 구간의 단일 소유자다. 렌더는 y - feetZ로만 투영한다. 벽·장애물은 지면 경로를 막는 장벽이며 도약·곡사도 통과시키지 않는다.

Matter 0.20.0의 x/y broadphase와 manifold를 유지하고 Detector 결과를 Pairs와 solver보다 먼저 필터한다. 물리 밀림·접촉 피해·돌진 CCD·일반 투사체·잔상은 같은 contactWindow에서 XY 접촉 시간과 Z 겹침 시간을 교차한다. 높이 분리 중 XY가 오래 겹쳐도 물리 반응이 없고 하강해 상단 높이를 만나면 z=0 전에 접촉할 수 있다. 빠른 수직 이동의 XY 통과는 beforeSolve에서 동시 접촉 위치로 제한하며 원래 적분 끝점을 보존해 후속 피해 판정이 다른 시간을 쓰지 않는다. Matter의 다각형 원 몸체에 닿도록 유효 접촉 구간 안으로 최대 1px만 보정한다. 착지 콜백은 높이·상태·표현만 정리하고 기존 450ms 접촉 재사용 대기와 돌진 중복 타격 방지는 유지한다.

원본: Rally 유닛 도형·도약, Budmori x/y/z·고정 착탄 궤적. BOUNKO의 지면은 x/y, 높이는 z이며 Rally의 축 이름을 복사하지 않았다.

28. 명시적 공격·새 병종·치유

평상 접촉은 피해 0이다. 종 Class는 Unit과 CAN-BE 능력을 조합하고 컨트롤러는 대상·접근 intent만 반환한다. 적·동행은 같은 공격·치유·재생·외형 구현을 사용하고 역할별 공격 함수를 복제하지 않는다. 플레이어 돌진과 동행 돌진은 collisionDamage, 모든 피해와 흡혈은 receiveHit의 공통 수신을 사용한다.

햇살 해바라기(brute): 준비 530ms → 광선 1,600ms → 회복 1,480ms, 250ms마다 대상 HP에 피해를 준다. 초기 사거리 420. 기본 광선 DPS 약 33.674는 기존 34피해·2,430ms 주기의 평균 DPS 약 13.992를 새 주기의 실제 6펄스에 맞춰 환산한 값이다. Rare부터 같은 표적에 실제 발사 1.5초 집중 시 ×1.5, Epic부터 3초 시 ×2.25. 사거리·차폐 경로 이탈이나 표적 사망은 집중을 즉시 초기화한다. 빨간 scout 꽃은 유지한다.
